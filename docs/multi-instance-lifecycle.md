# 多实例隐患分析与修复记录

分析基线：本仓库 `1.3.1`（提交 `4dfdca0`）。本记录描述工作分支中的修复，不表示 npm 上的 `1.3.1` 已包含这些改动。

## 支持范围与根因

原实现的 video、canvas、配置、事件及 WebGL 资源都属于实例，没有一个全局播放器对象覆盖其他实例。问题出在资源申请数量、异步请求的有效期及异常清理。它们在单实例中也存在，同页并发与频繁挂载会扩大资源压力。

| 隐患 | 触发与影响 | 本次修复 |
| --- | --- | --- |
| 额外检测上下文 | 每次 `new Render` 先在临时 canvas 检测 WebGL，再在输出 canvas 创建正式上下文。临时上下文未主动释放，只能等待浏览器回收；多实例更容易达到设备上限。 | 去掉临时检测画布。直接在正式 canvas 获取 WebGL；返回 null 时在同一 canvas 获取 2D。N 个 WebGL 实例只申请 N 个上下文。 |
| 重复帧循环 | 每次 `play()` 成功都启动一个循环，实例只记录最后一个 ID；暂停或销毁无法取消此前所有循环。 | 启动新循环前取消旧循环；循环代次检查阻止已入队的旧回调续订。重复、并发调用只保留一个有效循环。 |
| 错误取消回调 | 使用 `!animationId` 会把合法 ID `0` 当作不存在；依据最新配置决定取消方式，切换 `videoFrame` 后可能取消到另一种调度器。 | 用 `null` 表示无回调，并保存实际 request 对应的 cancel 函数及 video。覆盖 rAF、视频帧回调与定时器。 |
| 播放启动竞态 | 原生 `video.play()` 尚未完成时调用 pause、setSrc、destroy，晚到的成功结果仍会启动循环；销毁后的拒绝结果还可能访问空 config，覆盖原始错误。 | 播放请求带实例内序号；暂停、换源、结束、销毁使旧请求失效。旧结果不恢复 playing、不续订绘制、不发过期 onError，Promise 仍保留原始结果。 |
| 原生暂停未停止渲染 | 浏览器或外部 DOM 操作使 video 暂停，原 `pause` 事件只通知业务，绘制循环继续消耗资源。 | 原生 pause 事件同步取消绘制并使待完成播放请求失效。 |
| 初始化部分失败泄漏 | video 已挂载，着色器、纹理或缓冲申请失败；原构造 catch 只报告错误，且 destroy 在 gl 不存在时直接返回。 | 每项 GPU 资源一获得就保存；构造失败清理已获得的部分资源、video 与 canvas，再报告一次 onInitError。着色器编译/链接失败不再仅在 debug 下检查。 |
| 销毁重入和回调异常 | onDestroy 在字段清空前执行，重入可能重复清理；onError 抛错会跳过 destroy，onEnded 抛错会跳过 autoDestroy。 | 先标记已销毁，再取消请求与帧循环，移除事件并清理 GPU/DOM，最后通知 onDestroy。错误/结束清理通过 finally 保证执行。 |
| 上下文丢失无反馈 | 浏览器回收上下文后，video 和帧循环可能继续运行，画面却失效。 | 监听 webglcontextlost，通过现有 onError 传出事件并销毁受影响实例。销毁时先移除该监听，主动释放不产生伪错误。 |
| 限帧依赖 60Hz 整除 | 原代码以 `frame % (60 / fps)` 判断绘制，24fps 等不能整除60的设置会异常降帧，且不适配不同刷新率。 | 使用回调时间戳和间隔余量限帧；限帧状态保留在每个实例的当前循环内。 |

## 关键时序

播放请求在启动前记录请求序号，完成后验证序号、video 身份、销毁及原生暂停状态。只有当前有效请求能进入绘制循环。

```text
play A 发起 → pause / setSrc / destroy → 请求序号更新
           → play A 完成 → 序号过期 → 保留 Promise 结果，不再启动绘制

新循环开始 → 捕获循环代次 → 绘制并申请下一帧
取消循环   → 更新代次、取消对应 ID
旧帧晚到   → 代次过期 → 不修改新循环 ID，不再续订
```

销毁的顺序统一为：标记终态 → 使播放请求失效 → 取消帧回调 → 移除媒体监听 → 暂停并卸载媒体资源 → 释放渲染资源与画布像素缓冲 → 移除 DOM、清空引用 → 通知 onDestroy。重复调用直接返回。

## 兼容性与取舍

- 核心与 Vue 2、Vue 3、React 的公开方法、props 和类型签名保持不变，无新运行时依赖。
- `alphaScale=0` 保持原生 video 路径，不创建 canvas 或帧循环。
- 布局、Alpha 采样和自动尺寸计算没有改动。帧驱动仍优先视频帧回调，其次 rAF，最后定时器。
- `onDestroy` 现在严格在清理结束后触发；初始化失败只报告 onInitError，不伪装成一次成功实例的销毁。
- 换源终止旧的播放请求和绘制循环，需要播放新视频时再次调用 play。
- 上下文丢失采用明确失败并清理的行为，不在播放中自动切换到 2D 或重建。自动恢复涉及播放状态、资源重新申请、重试上限等新的契约，此次不引入。业务可在错误后重新创建实例或挂载组件。
- 回收多余上下文不等于取消设备限制。实际解码器数量、分辨率、DPR、帧率、显存和 WebView 策略仍决定并发能力；不能承诺统一的最大实例数或任意数量同时流畅播放。

## 回归验证

`tests/lifecycle.test.mjs` 用 Node 内置测试器直接加载构建后的核心 ESM。DOM、媒体播放 Promise、WebGL 调用和帧队列采用确定性替身，便于控制真实设备上难稳定复现的先后顺序。

验证包括：12 个并存实例的上下文计数与完全回收、100 次创建/销毁、两个播放实例的暂停/销毁隔离、三种调度器的重复播放与 ID=0、暂停/换源/销毁期间的晚到播放结果、新旧播放请求交错、已经入队的过期帧、原生 pause、驱动方式切换、部分 GPU 分配/编译/链接失败、上下文丢失、错误及销毁回调异常、三种渲染方式的 autoDestroy、24fps 限帧。

执行：

```bash
npm test
./node_modules/.bin/tsc --noEmit --skipLibCheck
git diff --check
```

核心、Vue 2、Vue 3、React 的 JS 与声明文件均通过生产构建。全量 `tsc --noEmit` 的第三方声明检查存在既有 Vue/React JSX 冲突、Vue 2/3 宏重复声明和 TypeScript 对 NoInfer 的支持问题；未修改 HEAD 的独立快照复现同样错误。此次没有调整依赖和 tsconfig 来掩盖该问题，源码检查使用 skipLibCheck。

最终结果：48 条回归全部通过；`tsc --noEmit --skipLibCheck` 与 `git diff --check` 通过。额外覆盖了首帧自动展示异常、onError 抛错时仍保留原生播放拒绝原因、同一视频地址的两个独立实例，以及底层取消、卸载或 GPU 清理异常时的幂等销毁。

本轮没有浏览器/手机真机并发压测。上述测试证明调用和清理契约，不证明真实解码、合成画质或设备能承受的最大并发量。
